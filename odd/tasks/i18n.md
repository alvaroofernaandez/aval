# i18n: aval in English and Spanish

Status: approved by the owner on 2026-11-23.

**Scope: the TUI and the human-facing CLI.** That means the hub and every view, the installer, settings, help overlays, and the messages commands print for people.

**Not in scope:** docs and the distributed skills stay English.

**Order:** this runs after the engineering-standards waves (S1 to S9). It touches almost every user-facing string, and S7 (errors as values, a single place for user text) is its foundation.

## Design

### Catalog
`internal/i18n` holds message keys and per-language tables.
- **Keys:** stable and dotted, for example `hub.entry.install.desc`.
- **English is the source of truth.** Spanish must cover every key.
- **Interpolation:** placeholders are named, for example `{count}` and `{path}`.
- **Plural forms:** `one`/`other` are enough for English and Spanish.
- **Dependencies:** check first whether `golang.org/x/text` is already in the module graph. A small stdlib table is preferred if it is enough, because "Go only" and a minimal dependency budget both apply.
- **Leaf package:** `internal/i18n` imports nothing internal. The S2 allowlist is amended through ADR 0002.

### Language selection
Precedence is flag > env > file > detection > default:
- **Flag:** `--lang`.
- **Env:** `AVAL_LANG`.
- **Config file:** a `language` key (`auto`, `en`, `es`) in the existing config file, with validation and a suggestion on a typo.
- **Detection:** `LC_ALL`, then `LC_MESSAGES`, then `LANG`. `es_*` selects Spanish.
- **Default:** English.
- **Settings view:** gains a Language row.

### What is never translated
Machine-facing output stays English:
- `--json`
- hook output, including deny reasons
- `statusline`
- error codes and sentinel identities
- log files
- generated files

These are read by scripts and by other tools.

### Copy rules
DESIGN.md section 10 applies in both languages:
- sentence case
- no exclamation marks
- no em dashes
- evidence over "Success"
- every error says what, where and the fix

Spanish uses neutral, professional Spanish with no regional forms.

### Layout
Spanish runs longer. The width and height invariants, wrapping and truncation must hold in both languages.
