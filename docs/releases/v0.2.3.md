# v0.2.3

**One reminder, not a loop, and guards that keep the codebase small.**

2026-11-23 &nbsp;·&nbsp; stable &nbsp;·&nbsp; **English** &nbsp;·&nbsp; [Español](v0.2.3.es.md)

</div>

## What this release means for you

When an agent edits UI files and ends its turn without a render, the design pipeline's Stop hook asks once for a screenshot. On Linux that request could repeat on every stop of the session, because the file that records "already asked" got its time from a coarser clock than the edit it covered. It now asks once, as designed, on every system. The rest of the release is for anyone who works on aval itself: one page that maps the repository, and three tests that keep dependencies, package docs, and file and function sizes from growing unnoticed.

## Highlights

| **One reminder per edit** | **A one-page map** | **A dependency budget** |
| :-- | :-- | :-- |
| The render request no longer repeats on Linux. | `ARCHITECTURE.md`: every package, the data flow and where a change goes. | Every direct dependency has its reason in writing; two unused ones are gone. |
| **Size limits** | **A ratchet, not a rewrite** | **Kept true by tests** |
| 500 lines per file, 60 per function, complexity 15. | Today's 90 exceptions are ceilings that may only come down. | Each page and list fails `go test` the moment it drifts. |

## The render reminder

| Situation | Before | Now |
| :-- | :-- | :-- |
| UI edited, no render, first stop | asks for a render | asks for a render |
| Second stop, same edit | could ask again on every stop (seen on Linux CI) | silent |
| A later UI edit | asks again, once | asks again, once |

## For contributors: guards that keep aval maintainable

| Guard | What fails `go test` | Where |
| :-- | :-- | :-- |
| Dependency budget | a direct dependency without a reason, a stale row, a direct import marked `// indirect` | [docs/dependencies.md](../dependencies.md), `tests/dependencies_test.go` |
| Architecture page | a package without a row, a row for a removed package, a page over 150 lines | [ARCHITECTURE.md](../../ARCHITECTURE.md), `tests/architecture_doc_test.go` |
| Size and complexity | new code over a limit, an exception that grows, an exception that shrank but was not lowered | `tests/quality_test.go`, `tests/testdata/quality-allowlist.txt` |

```sh
go test ./tests/ -run Quality -v     # the ten largest files and functions, and the most complex
```

The size limits started from measured values: 11 files over 500 lines, 36 functions over 60 lines and 43 over complexity 15 (largest file `internal/core/backup/backup.go`, 1102 lines; most complex function `dispatch` in `cmd/aval/main.go`, 46). They pass today and can only get better.

## Fixes

- **design:** the render reminder of the Stop hook blocks once per UI edit on Linux too

## Upgrade notes

> [!IMPORTANT]
> `config/opencode/package.json` no longer lists `opencode-subagent-statusline` and `unique-names-generator`, which nothing used. An existing `~/.config/opencode/node_modules` keeps them until OpenCode reinstalls its packages; nothing breaks either way.
