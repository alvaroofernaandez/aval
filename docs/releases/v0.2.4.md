# v0.2.4

**The plan gate sees every file in the repository, and every hook is fuzzed in CI.**

2026-11-23 &nbsp;·&nbsp; stable &nbsp;·&nbsp; **English** &nbsp;·&nbsp; [Español](v0.2.4.es.md)

</div>

## What this release means for you

While a plan in `odd/tasks/` has no deck, the plan gate denies edits outside `odd/`. It decided whether a file was outside the repository by checking whether its relative path started with two dots, so a file inside the repository whose name starts with two dots, such as `..notes.go` or `..cache/x.go`, slipped through. It now treats a path as outside only when it really leaves the root. The rest of the release hardens the hooks: every hook that reads JSON is fuzzed with arbitrary input, and CI runs a short fuzzing pass on every push. Patch releases such as this one now publish without a manual approval.

## Highlights

| **No gap in the plan gate** | **Hooks fuzzed** | **Fuzzing in CI** |
| :-- | :-- | :-- |
| Names that start with two dots are gated like any other file. | Six JSON hooks never panic, never fail and never block on input they cannot parse. | A 20 second pass per fuzz target on every push and pull request. |

## The plan gate

| File edited while the plan has no deck | Before | Now |
| :-- | :-- | :-- |
| `src/main.go` | denied | denied |
| `..notes.go`, `..cache/x.go` (inside the repository) | allowed | denied |
| `odd/tasks/plan.md`, `docs/decks/plan.deck.json` | allowed | allowed |
| a file outside the repository | allowed | allowed |

## Fuzzing the hooks

| Target | What it checks |
| :-- | :-- |
| `FuzzPlanGatePath` | for any relative name, the gate agrees with an independent oracle built from the cleaned path |
| `FuzzHookInput` | `lessons`, `design-gate`, `plan-gate`, `design-shot-stop`, `rate-guard` and `repo-profile` return no error, print nothing or one JSON value, and never deny or block on invalid JSON |
| `FuzzLessonMatch`, `FuzzLessonBody` | the lesson triggers and bodies (since v0.2.2) |

```sh
go test ./cmd/aval -run '^$' -fuzz '^FuzzHookInput$' -fuzztime 60s
```

A finding turns CI red, which also blocks releases, and the job keeps the failing input as an artifact. `rtk-rewrite` and `pre-push` are not fuzzed: they start processes. Fuzzing the guard on shell commands waits for #24.
