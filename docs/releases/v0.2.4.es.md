# v0.2.4

**La puerta del plan ve todos los archivos del repositorio, y cada hook se somete a fuzzing en la CI.**

2026-11-23 &nbsp;·&nbsp; estable &nbsp;·&nbsp; [English](v0.2.4.md) &nbsp;·&nbsp; **Español**

</div>

## Qué significa esta versión para usted

Mientras un plan de `odd/tasks/` no tiene deck, la puerta del plan deniega las ediciones fuera de `odd/`. Decidía si un archivo estaba fuera del repositorio comprobando si su ruta relativa empezaba por dos puntos, de modo que un archivo dentro del repositorio cuyo nombre empieza por dos puntos, como `..notes.go` o `..cache/x.go`, se colaba. Ahora una ruta solo se considera fuera cuando sale de verdad de la raíz. El resto de la versión refuerza los hooks: cada hook que lee JSON se somete a fuzzing con entradas arbitrarias, y la CI ejecuta una pasada corta de fuzzing en cada push. Las versiones de parche como esta se publican ya sin aprobación manual.

## Lo más destacado

| **Sin hueco en la puerta del plan** | **Hooks con fuzzing** | **Fuzzing en la CI** |
| :-- | :-- | :-- |
| Los nombres que empiezan por dos puntos pasan por la puerta como cualquier otro archivo. | Seis hooks JSON nunca entran en pánico, nunca fallan y nunca bloquean con una entrada que no pueden leer. | Una pasada de 20 segundos por objetivo de fuzzing en cada push y pull request. |

## La puerta del plan

| Archivo editado mientras el plan no tiene deck | Antes | Ahora |
| :-- | :-- | :-- |
| `src/main.go` | denegado | denegado |
| `..notes.go`, `..cache/x.go` (dentro del repositorio) | permitido | denegado |
| `odd/tasks/plan.md`, `docs/decks/plan.deck.json` | permitido | permitido |
| un archivo fuera del repositorio | permitido | permitido |

## Fuzzing de los hooks

| Objetivo | Qué comprueba |
| :-- | :-- |
| `FuzzPlanGatePath` | para cualquier nombre relativo, la puerta coincide con un oráculo independiente construido a partir de la ruta limpia |
| `FuzzHookInput` | `lessons`, `design-gate`, `plan-gate`, `design-shot-stop`, `rate-guard` y `repo-profile` no devuelven error, no imprimen nada o imprimen un solo valor JSON, y nunca deniegan ni bloquean con JSON no válido |
| `FuzzLessonMatch`, `FuzzLessonBody` | los disparadores y cuerpos de las lecciones (desde v0.2.2) |

```sh
go test ./cmd/aval -run '^$' -fuzz '^FuzzHookInput$' -fuzztime 60s
```

Un hallazgo pone la CI en rojo, lo que también bloquea las versiones, y el job conserva la entrada que falla como artefacto. `rtk-rewrite` y `pre-push` no se someten a fuzzing: inician procesos. El fuzzing de la guardia de comandos de shell espera a #24.

## Correcciones
