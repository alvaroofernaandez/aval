# v0.2.2

**Globs that always work, in any language.**

2026-11-23 &nbsp;·&nbsp; stable &nbsp;·&nbsp; **English** &nbsp;·&nbsp; [Español](v0.2.2.es.md)

</div>

## What this release means for you

Two kinds of patterns in aval decide what happens to your files: the triggers of a lesson (which edit gets which advice) and the permission rules that `aval sync` merges. Both had blind spots. A lesson whose trigger had an unclosed `{` was dropped without a word, and any pattern with a non-ASCII character, such as `docs/ñ.md` or `café/`, never matched anything. A long lesson could also be cut in the middle of a character. Fuzz tests found all of it, and from this release patterns behave the same whatever the language of your paths.

## Highlights

| **No silent drops** | **Non-ASCII paths match** | **Clean lesson text** |
| :-- | :-- | :-- |
| A trigger with an unclosed `{` still compiles and keeps the lesson. | `docs/ñ.md` matches `docs/ñ.md`, in lessons and in permission rules. | A body over 600 bytes is cut on a character boundary, never inside one. |

## What changed

| Pattern | Before | Now |
| :-- | :-- | :-- |
| Lesson trigger `src/{a` | invalid regexp, trigger dropped | matches `src/a` |
| Lesson trigger `docs/ñ.md` | never matched | matches `docs/ñ.md` |
| Permission rule `Read(docs/ñ.md)` | never matched | matches `docs/ñ.md` |
| Lesson body of 600+ bytes ending in `ñ` | cut inside the character | cut before it |

## Fixes

- **lessons:** trigger globs always compile, match non-ASCII literals, and bodies keep whole characters ([#45](https://github.com/alvaroofernaandez/aval/issues/45), lessons slice)
- **sync:** permission globs match non-ASCII literals

## Known limits

- #45 stays open: `FuzzGuardCommand` waits for the guard of #24, and the CI fuzz job is not part of this release. The fuzz seeds run in every `go test ./...`.
